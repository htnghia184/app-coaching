## Proposed content contract
Use strict JSON Schema (draft 2020-12) + runtime validator accepting unknown, discriminated unions, reject unknown fields, stable IDs, schema version independent of content version. No arbitrary HTML/scripts, URL schemes or embedded answer keys. Validate references, uniqueness, bounds, dependency DAG, type compatibility and publication gates on server and client. Public learner manifest: moduleId, code, contentVersion, schemaVersion, title, locale, skill, level, estimatedMinutes, prerequisites[], outcomes[] (versioned IDs and observable statements), sourceRevisionRef (opaque), stages[] (stable id, title, minutes, activities[]), completionPolicyRef, reviewPolicyRef. Stage count/order authored, not hardcoded six. Each activity: id, type, typeVersion, title, instructions, estimatedMinutes?, payload, responseSpec, completionRule, feedbackMode, references[]. Separate private package: source trace, correct answers/explanations, rubric anchors and scoring policies, media resolver mappings, reviewer metadata. Public manifest may show criteria/instructions but not keys. Server returns authorized feedback only after configured batch submission; do not leak keys in bundle, repository or anonymous API.

### Activity registry and response contract
- lesson: typed blocks paragraph, comparison, table, annotated transcript, callout, examples; no response unless acknowledgment.
- media: provider enum youtube/audio; opaque assetRef resolved for enrolled users/admin preview, captions/transcript, explicit missing state; no autoplay requirement.
- choice: question with one or more independently identified choice fields, option IDs, single/multi selection; classification and M04 Discover comparison use same primitive.
- matching: one prompt and named option groups, selections by group; no pair-only limitation.
- text_response: named fields with constrained_blank or open_response policy; accepted variants for closed blanks defined privately, open work uses exemplar/self/coach feedback, optional second fields; dependencies on previous exercise response or authorized feedback, not hidden keys.
- recording: prompt, optional scaffold/keywords/preceding text, target seconds (guidance vs assessed bounds explicit), local preview/re-record, permission/error handling; persisted evidence references for real mode.
- reflection: checklist or matrix keyed by prompt and criterion, linked evidence playback, scored=false by default; permit unselected items without claiming mastery.
- evidence_submit: references existing or fresh recording/text evidence plus reflection; immutable submission snapshot and required item IDs; no recording duplication for M02.
Each response event has attemptId, moduleVersion, activityId, itemId, fieldId, responseVersion, timestamp, typed value or private media reference. Feedback policy: immediate/reveal-after-response, after-batch, exemplar, coach-only, none. Practice retries preserve history; allow correct alternative text when source requires it. No player special case by module ID.

## Mastery and revisions
M01/M03/M04 use rubric_sum: four criteria scored 0–2, min total 6, no zero, fresh Verify audio 20–30s; separate rubric IDs/anchors per module. M02 uses per_item_pass: six Apply items; at least five pass, no item repeats whole question; individual criteria suitable question pattern, grammar, no repetition; fourth reflection criterion is not scored. Submit all six for completion; no fresh Verify audio. Revision requests specify item IDs; reuse explicitly linked prior evidence for unchanged items, keep original reviews, do not overwrite recordings. Coach final decision and reason recorded, mastery distinct from module completion and IELTS band. Any override rules must be explicitly approved and audited, never inferred from UI.

## Import/publishing
Private source package → parse → strict validation → source comparison (text, tables, emphasis, question options, key, rubric, timing) → resolve media → admin preview → academic approval → immutable publish. Record source file revision, content hash, reviewer, timestamp. Content team can import without React change. Missing required asset or unresolved key blocks publication; draft preview may show missing media with fallback. Keep unlisted IDs out of public GitHub; authorized resolver still cannot prevent link sharing. Do not auto-publish or modify source Word. Existing tasks, submissions/revisions and RLS remain baseline.
