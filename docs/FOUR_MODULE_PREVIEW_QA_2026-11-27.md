# Four-module engine preview QA

Branch from `88489e9`. Four authoritative SharePoint Word packages were re-opened read-only on 2026-11-27 (text extraction; rendered layout and embedded media still unverified). Their structural forms are represented in `fourModulePreviews.ts`: six stages each; Practice units 10/16/12/10; recording slots 5/7/5/7; M02 Verify reuses six Apply recordings and requires per-item coach review; M01/M03/M04 require fresh Verify audio and a four-criterion 6/8 rule with no zero. M04 Discover has no recorder. The M04 source explicitly requires **WHO, WHAT AND WHEN**; the wording in the subsystem spec and preview has been corrected.

The public preview intentionally uses generic placeholders. It is **not a source-parity approved learner package**. Word wording, options, answer keys, explanations, rubric anchors, tables, emphasis and media remain in SharePoint and must enter a private, versioned import with academic comparison before publication. No private teaching assets or YouTube IDs are committed. The preview's outcome labels and criterion names are structural summaries; the author must approve exact wording. Open responses are never exact-match graded. Rule simulation is not a coach assessment.

The proposed `module-media-resolver` Edge Function reads `MODULE_MEDIA_MAP_JSON` and `MODULE_AUDIO_BUCKET` only from server environment, checks caller identity and assigned task/module before resolving YouTube or audio, and returns expiring signed audio URLs through caller RLS. It has **not** been deployed or authenticated E2E tested. The public preview performs no media resolution or student-progress write; missing media is explicit. Video content and sample-audio mappings remain unverified. Do not publish a module until the source parity report and media access checks pass.
